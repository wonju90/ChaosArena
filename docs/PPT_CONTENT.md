## ChaosArena

### K8s Self-Healing을 게임으로 체험하는 멀티 리전 데모 프로젝트

- 쿠버네티스 자가치유(Self-Healing)를 눈으로 보고, 직접 장애를 일으켜보는 대시보드
- 1인 프로젝트 — 인프라 설계부터 CI/CD, 모니터링, 프론트엔드까지 전체를 직접 구축
- 발표자: (이름/소속 채워넣기)

---

## 이 프로젝트를 만든 이유

- 쿠버네티스는 "장애가 나면 알아서 복구한다"고 배우지만, 그 과정을 실제로 본 적은 별로 없다
- 관리형(managed) 클러스터가 아니라 **자체 kubeadm 클러스터를 직접 구축**해서, 그 과정에서
  실제로 겪는 문제들까지 전부 경험하고 기록하고 싶었다
- 목표는 "기능을 완성하는 것"이 아니라 **"부딪힌 문제를 어떻게 진단하고 풀었는지"를 남기는 것**
- 결과: 프로젝트 로그에 트러블슈팅만 38개 항목이 기록된 실전 인프라 구축기

---

## 핵심 한 줄 데모

- 화면에서 "Chaos" 버튼을 누르면 → 실제 쿠버네티스 파드가 그 자리에서 삭제됨
- 몇 초 안에 쿠버네티스가 새 파드를 자동으로 재생성
- 그 복구 시간을 측정해서 S/A/B/C 랭크·콤보·하이스코어로 채점하는 게임성 부여
- 앱 자기 자신이 "장애가 나고 복구되는 대상"이자 "그 상태를 보여주는 대시보드"인 이중 구조

---

## 기술 스택

- **애플리케이션**: Python Flask, Prometheus client, Kubernetes Python client
- **프론트엔드**: Vanilla JS(폴링 기반 실시간 갱신), Tailwind CSS, Chart.js
- **인프라**: NHN Cloud, Terraform(IaC), kubeadm 자체 구축 클러스터
- **네트워크/CNI**: Calico
- **멀티 리전**: NHN Cloud DNS Plus GSLB (Active/Standby Failover)
- **CI/CD**: Jenkins(빌드+서명), ArgoCD(GitOps 배포), cosign(이미지 서명)
- **모니터링**: Prometheus, Grafana, Alertmanager → Slack
- **데이터**: Redis (리더보드/이력 영속화)

---

## 전체 아키텍처

- 사용자 → **GSLB**(DNS 기반 리전 라우팅, TTL 30초) → **KR1(판교)** / **KR2(평촌)** 중 Active 리전
- 각 리전은 완전히 **대칭 구조** — Ingress → chaos-demo(Pod) → Redis, 그리고 각자 독립된
  Jenkins/ArgoCD/Prometheus까지 리전마다 전부 보유
- 소스 코드 push → 양쪽 리전 Jenkins가 각각 감지 → 이미지 빌드+서명 → 별도
  GitOps 매니페스트 저장소에 커밋 → 각 리전 ArgoCD가 감지해서 자기 리전에 배포
- 왜 대칭 구조인가: 한쪽 리전(원래 메인이던 KR2)이 통째로 죽어도, 반대편(KR1)이 독립적으로
  빌드·배포·모니터링을 계속할 수 있어야 진짜 이중화이기 때문 (SPOF 제거)

---

## 핵심 기능 1 — 게임화된 Self-Healing

- Chaos 버튼(이지/하드/보스전 난이도)으로 실제 파드를 삭제
- 복구 시간 기반 S/A/B/C 랭크 + 연속 성공 콤보 + 하이스코어 기록
- Redis 기반 리더보드로, 파드가 재시작돼도(모든 자동 배포 포함) 기록이 유지됨
- CPU 부하 시뮬레이션 → HPA(오토스케일러)가 실제로 3→6개로 스케일 아웃하는 것까지 체험 가능

---

## 핵심 기능 2 — CI/CD 파이프라인 (완전 자동화)

- GitHub push → Jenkins Webhook 트리거 → Kaniko로 이미지 빌드 → NHN NCR(비공개 레지스트리)에 push
- **cosign으로 이미지에 서명** — 서명 안 된 이미지는 정책상 pull 자체가 차단됨(공급망 보안)
- 서명된 이미지 정보를 GitOps 매니페스트 저장소에 커밋
- **ArgoCD가 Pull 방식(GitOps)으로 감지해서 배포** — Jenkins는 클러스터에 배포 권한이 아예 없음
- 배포 실패 감지 시 자동 롤백 커밋까지 자동화
- 이 전체 파이프라인 소요시간도 게임 랭크(S/A/B/C)로 채점해 CI/CD 전용 탭에서 시각화

---

## 핵심 기능 3 — 멀티 리전 + GSLB 페일오버

- KR1(판교)/KR2(평촌) 두 리전을 Active/Standby로 구성
- Active 리전이 완전히 응답 불가 상태가 되면, GSLB가 자동으로 Standby 리전으로 트래픽 전환
- **실측 검증**: 리전을 강제로 다운시킨 뒤 약 67~80초 후 실제 DNS 페일오버 확인, 복구 후
  failback(원래 리전으로 복귀)까지 양방향 실측 완료
- TTL(30초) 값만으로 전환 속도가 결정되는 게 아니라, 헬스체크 실패 판정 기준까지 합쳐져서
  실제 체감 전환 시간이 결정된다는 것도 실측으로 확인

---

## 핵심 기능 4 — 인프라 지도 (`/infra` 실시간 대시보드)

- 양쪽 리전의 Ingress→Deployment→ReplicaSet→Pod 계층을 실시간으로 시각화
- 리전이 죽으면 카드가 즉시 빨갛게 반응(수 초 내) — 이건 앱이 직접 확인한 결과
- 그 위의 GSLB 배지는 30~80초 뒤에 늦게 전환됨 — **"리전 헬스체크"와 "실제 DNS 전환"이 서로
  다른 타임스케일이라는 것을 한 화면에서 보여주는 게 이 기능의 핵심**
- Redis/모니터링/Jenkins/ArgoCD 4개 구성요소 상태를 실제 HTTP 헬스체크로 표시(장식이 아님)
- 활성 알림 배지, GSLB 페일오버 이력, 상태 지속시간 실시간 카운터까지 제공

---

## 핵심 기능 5 — 모니터링 & 알림

- Prometheus + Grafana로 파드별/클러스터 전체 메트릭 수집
- Alertmanager가 파드 다운/CPU 급증/에러율 급증을 감지해 **Slack으로 실시간 알림**
- 알림 메시지를 한글화하고, 이 랩 환경 특성상 항상 발생하는 구조적 노이즈 알림(단일 노드
  etcd 등)은 규칙 자체를 꺼서 진짜 신호만 남김
- 반대로 파드 크래시루프처럼 실제로 의미 있는 신호는 의도적으로 그대로 살려둠

---

## 컨트롤 플레인 이중화 — 단일장애점(SPOF) 제거

- 처음엔 Jenkins/ArgoCD/모니터링이 KR2에만 있어서, **KR2가 죽으면 KR1이 멀쩡해도 배포 자체를
  못 하는 구조적 약점**이 있었다
- KR1에도 Jenkins/ArgoCD/kube-prometheus-stack을 통째로 복제해서 완전 대칭 구조로 전환
- **실측 검증**: KR2 Jenkins를 완전히 내려놓은 상태에서 KR1이 혼자 빌드→서명→배포까지 끝내는
  것까지 확인 완료

---

## 트러블슈팅 하이라이트

- **Terraform이 운영 중인 서버를 통째로 재설치할 뻔한 사고를 사전에 막음**: `terraform plan`에
  뜬 사소해 보이는 diff 하나를 무시하지 않고 클라우드 프로바이더 소스 코드까지 읽어서, 방치했다면
  살아있는 클러스터가 파괴적으로 재설치(Rebuild)됐을 상황을 원인 규명 후 근본적으로 해결
- **파드끼리 네트워크가 안 되는 문제**: 클라우드의 네트워크 보안 모델(anti-spoofing)과 CNI(Calico)의
  기본 설정이 충돌하던 것을, 인프라 레이어부터 하나씩 검증해가며 근본 원인까지 좁혀서 해결
- **Slack 알림이 안 오는 문제**: 서로 무관해 보이는 원인 3개(Helm 옵션 함정, Secret 네임스페이스
  불일치, 리소스 병합 방식으로 인한 설정 유실)가 겹쳐있던 것을 레이어별로 하나씩 벗겨가며 해결
- 프로젝트 전체 트러블슈팅 로그 38개 항목이 `PROJECT_LOG.md`에 증상→원인→해결 형식으로 기록됨

## 실측 검증 요약

- GSLB 페일오버: 리전 다운 → 약 67~80초 후 실제 전환, failback까지 양방향 확인
- HPA 오토스케일링: CPU 부하 시 3 → 6 파드로 실제 스케일 아웃, 부하 해제 후 5분 안정화 창 거쳐 6 → 3
- CI/CD 파이프라인: push 한 번으로 빌드→서명→GitOps 배포까지 사람 개입 없이 완전 자동 완주
- 컨트롤 플레인 이중화: 한쪽 리전의 CI/CD 스택을 완전히 꺼도 반대쪽이 독립적으로 배포 지속
- 리더보드(Redis): 파드가 재시작돼도(자동 배포 포함) 기록 유지 검증
